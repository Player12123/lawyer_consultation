# 生产接口部署与配置手册

> 修改标有 `REPLACE_` 的变量即可；真实值只写入云端密钥管理服务或本机忽略的 `.env.local`，**不要**写入代码、文档截图、Git 或工单。

## 1. 已实现的安全边界

- 浏览器只调用同源 `/api/v1/*`；MySQL、短信和模型服务不对浏览器开放。
- 登录验证码为随机 6 位码，5 分钟有效、一次性消费、最多验证 5 次；同手机号 60 秒最多一次、每小时最多五次。
- 登录状态保存在 `HttpOnly`、`Secure`、`SameSite=Strict` Cookie；数据库只保存会话令牌哈希。新登录会撤销旧会话。
- 每个业务对象均带 `tenant_id`，后端从会话取得租户，不采信浏览器提交的租户 ID。
- AI 调用仅从后端发出；手机号和身份证号会先做基础脱敏，密钥不会进入浏览器。
- 审计只记录必要的操作元数据和手机号/IP 哈希，**不写**验证码、密码或咨询正文。

## 2. 必须手动填写的配置

1. 复制 `.env.example` 为 `.env.local`（本机）或将同名变量写入腾讯云/阿里云的密钥管理服务。需要改本地文件名时，以 `ENV_FILE=/安全路径/文件名` 指定；生产不应使用文件承载密钥。
2. 填写 `TENANT_ID`：这是受控开户流程创建的 26 字符租户 ID。每个客户独立域名/API 部署固定一个值，浏览器没有、也不能传入该参数。
3. 把以下三个 `*_PEPPER` 改为各不相同的随机 32 字节以上字符串。它们用于哈希，不可丢失；丢失后所有现有会话和验证码将失效。
4. 填写 `DATABASE_URL`、`DB_SSL_CA` 与 `DB_SSL_REJECT_UNAUTHORIZED=true`。数据库账号只授予本应用所需的表权限，禁止使用 root。
5. 生产短信使用百事通网关时，设 `SMS_PROVIDER=bestone` 并填写 `SMS_BESTONE_*`；必须使用供应商提供的 HTTPS 或内网地址。短信内容模板保留 `{code}` 和 `{minutes}` 两个变量。
6. 生产 AI 设 `AI_MODE=enabled` 并填写 `AI_*`。模型端点使用受控 HTTPS 服务，并确认供应商不会将输入用于训练。

未完成配置时，短信和 AI 会明确拒绝服务；这是一项刻意的 fail-closed 保护，不会用假验证码或模拟答案代替。

## 3. 部署拓扑（推荐）

```text
用户浏览器 → WAF/CDN → HTTPS 反向代理
                         ├─ /        前端静态站点
                         └─ /api/*   Node API（127.0.0.1:8788）
                                      ├─ MySQL（同 VPC、TLS、无公网）
                                      ├─ 百事通短信网关（HTTPS/内网，仅出站）
                                      └─ 模型服务（受控 HTTPS）
```

建议在中国大陆同一地域的 VPC 内部署两台 API 实例，前置负载均衡/WAF。每个客户专属域名的 API 实例使用固定 `TENANT_ID`；这是租户选择的唯一来源。反向代理将 `/api/` 转发到 API 后，前端无需设置 `NEXT_PUBLIC_API_BASE_URL`；保持它为空能避免 Cookie 跨域问题。

应用启动命令为 `npm run api:start`。仅监听 `127.0.0.1:8788` 是有意设置：必须经 Nginx/CLB 的 HTTPS 入口访问，不能直接暴露端口。

## 4. 数据库发布顺序

1. 对备份库执行 `npm run db:migrate`，检查租户、用户、会话、验证码和审计表。
2. 验证每一张业务表均不能跨租户查询；验证 API 数据库账号无法执行 DDL 或访问无关库。
3. 再迁移生产库。发布前先备份，并准备回滚窗口；不要跳过迁移直接上线 API。
4. 为每个客户创建一个 `tenants` 记录。首次短信验证会自动创建普通坐席账户；如需创建首位管理员，临时设置 `BOOTSTRAP_ADMIN_PHONE`，管理员首次登录成功后立即清空该变量并重启 API。

## 5. 上线验收清单

- [ ] 数据库没有公网地址，安全组只允许 API 子网；已启用 TLS 与备份。
- [ ] WAF 启用限流、恶意请求和大模型输入/输出安全检测。
- [ ] 所有密钥来自密钥管理服务，日志和告警没有完整手机号、Cookie、验证码、Authorization 或咨询原文。
- [ ] 测试验证码重放、超过五次错误、短信频率限制、失效会话、新登录挤掉旧登录和跨租户访问。
- [ ] 抽测 AI 回答：事实不足时提示补充信息；不输出虚构法条、案例或案号。
- [ ] 建立咨询原文不超过 90 天、审计事件不少于 180 天的自动清理任务；清理任务必须可审计。
- [ ] 完成等保、个人信息、生成式 AI 服务及客户合同要求的专项审查后再对外开放。

## 6. 需要你确认或提供的项目资料

- 最终云厂商、地域、域名与证书。
- 腾讯云短信的已审核签名、模板 ID、SDK App ID 与最小权限子账号。
- 已签订数据处理条款的 AI 服务地址、接口密钥和模型名称。
- 每个首批客户的租户名称、管理员名单和 SSO 参数（如启用 SSO）。

这些资料中的密钥不要发送到聊天中；填入密钥管理服务即可。
