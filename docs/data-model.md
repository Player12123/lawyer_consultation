# 数据模型基线

## 身份与组织

- `tenants`：客户组织边界。
- `user_groups`：租户内工作组。
- `users`：用户资料、分组、角色、状态和逻辑删除标记。首次短信登录自动创建普通用户。
- `tenant_system_admins`：每个租户唯一的系统管理员指针，以数据库主键保证“一租户一个”。
- `verification_codes`：只保存验证码哈希、用途、有效期、使用状态和尝试次数。
- `sessions`：只保存会话令牌哈希，可逐个撤销。
- `password_credentials`：旧结构兼容表；当前产品不提供密码登录，不新增密码凭据。

## 咨询

- `consultation_contexts`：连续聊天中的上下文段。用户点击“清空聊天记录”只结束当前上下文并开始新上下文，不删除历史记录。
- `consultation_entries`：一条律师问题对应一条记录，保存加密的问题、加密的回答、法律业务类型、分类来源、法条/类案匹配结果、处理状态和提示词版本。
- 每条记录带客户端请求幂等键，避免网络重试造成重复咨询量。
- 法律业务类型按每个问题独立判断；短检索指令可继承上一条业务类型。

## 智能体与内部记录

- `prompt_versions`：按用途和版本保存提示词，只有一个启用版本；咨询记录关联实际使用的版本。
- `service_error_logs`：仅供产品运维内部排障，内容脱敏，按 `expires_at` 清理，保留 200 天。
- `audit_events`：追加写入的身份、权限、分组、账号状态、手机号换绑、提示词发布和敏感查看事件；不保存咨询全文。

## 客户可见统计

- 咨询量：`consultation_entries` 中已提交的问题数，失败问题可单独标识但不能悄悄丢失。
- 案由/业务类型分布：按每条问题的 `business_type` 聚合。
- 不统计在线时长、活跃度、字数、法条检索量和类案检索量。
