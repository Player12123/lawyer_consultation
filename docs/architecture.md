# 口袋智能律师：目标架构基线

本文是当前迭代的实现边界。代码、数据库和界面如与本文冲突，以本文和 `permissions.md`、`data-retention.md` 为准。

## 产品边界

- 产品服务对象是正在接听法律咨询电话的律师，核心目标是快速提供有依据的法律建议、法条和类案。
- 咨询区只有一条连续时间线，不使用“新建话题/多会话”模型。
- 每次律师发送的问题都是独立的咨询统计单位，并独立判断法律业务类型。
- “继续查法条”“找类似案例”等短指令优先继承上一问题的法律业务类型和必要上下文。
- 法条检索次数、类案检索次数不作为客户侧统计指标。

## 服务端边界

- 浏览器只保存临时交互状态；用户、权限、咨询记录、提示词版本和统计均以 MySQL 为唯一事实来源。
- 所有身份、租户、分组和角色权限均在服务端逐个接口校验，不能依赖前端隐藏按钮。
- AI、短信、法条和类案供应商密钥只从服务端环境变量读取，不下发浏览器、不写入日志。
- 咨询正文与 AI 回答加密后入库；审计日志和技术错误日志不得保存验证码、密钥或咨询全文。
- 外部法律能力失败时允许 AI 主流程降级回答，但必须记录脱敏后的内部技术错误。

## 模块职责

- `features/auth`：短信登录、会话撤销、手机号换绑和服务端身份解析。
- `features/user`：用户资料、状态、角色和分组。
- `features/consultation`：连续咨询上下文、逐问题记录、法律类型归类、AI/法条/类案编排。
- `features/admin`：分组管理、成员权限和客户可见的咨询量/案由统计。
- `features/audit`：不可由客户修改的安全与管理操作审计。
- `db/schema`：结构定义；`db/migrations`：数据库演进的唯一可信记录。

## 当前迭代不实施

- 正式部署、生产环境参数、运维平台、备份方案和完整自动化测试体系。
- 用户“活跃度”、实时在线状态、连续在线时长。
- 客户侧错误率、响应耗时、法条检索量、类案检索量等技术指标。

这些事项不应阻碍当前数据结构和权限边界按生产级方式建设。
